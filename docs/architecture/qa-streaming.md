# Interactive document Q&A

Existing complete JSON POST `/organizations/{org}/contracts/{id}/questions` and `/organizations/{org}/portfolio/questions` retain their schemas. Add `/stream` to either path to opt into `application/x-ndjson`. The BFF already forwards `response.body`; it now preserves streaming headers/cancellation, not a fabricated JSON-buffering fix. No automatic replay/fallback after partial text: that could duplicate a paid generation.

Every frame has `type`, stable `request_id`, and increasing `seq`. `status` and `evidence` are provisional; `answer` carries provisional `delta` text. Success is only `final` with `completed=true`, `provisional=false`, and a full validated result. Failures after headers emit redacted `error` plus incomplete final; disconnects emit no completed result. UTF-8 and NDJSON framing may cross arbitrary chunks. Client frame/source/answer bounds and validation reject malformed, reordered, mismatched-identity or incomplete streams.

Authorize/retrieve before headers. Fresh membership/JWT/source/evidence checks run periodically and immediately before final audit. **Follow-up correction:** the original #21 stream still injected a yielded `UserDep`, holding an auth SELECT connection for unchanged returning users. `stream_identity` now owns/closes a short session and returns only a string ID; global dependency scope is unchanged. Each generation/revalidation unit has independent thread-local session ownership. Actual QueuePool tests (including PostgreSQL) run six paused streams through a two-connection/no-overflow pool, assert baseline checkouts during provider waits and after every completion/error/timeout/disconnect, and permit unrelated authenticated reads. Changed/deleted/expired/revoked evidence cannot become a completed answer. Final model citations must refer to the prepared excerpts. Partial text can never create an approval, reserve budget, dispatch an action or stand in for a completion receipt. Audits contain metadata, not question/answer/document bodies. A disconnect after a committed final decision can still lose network delivery, as for ordinary HTTP; clients must not replay blindly.

Bound source materialization to 24 SQL-ranked authorized candidates, considering relevant older documents over the full tenant collection rather than newest-N. Search is token/LIKE bounded and escaped; full database scan/selectivity cost is still data-dependent. Retention determines whether retained source or the existing structured review is eligible. Full reviews and sources are not downloaded for every portfolio record.

**Follow-up correction:** #21 repeated that full rank/materialization at every stream check. Streams now rank once, prepare the answer, and snapshot only the source contracts actually used by its excerpts (at most eight, a subset of the 24 candidates). Subsequent checks select those exact tenant-scoped IDs, title, review ID, retention eligibility, and a database-computed SHA-256 of the effective evidence. PostgreSQL uses built-in `sha256(convert_to(...,'UTF8'))`; SQLite registers the deterministic equivalent on its own connections. No extension, column, timestamp assumption or migration is required. This detects in-place source/analysis replacement and review identity changes without transferring all source bodies again. Changing an unrelated document never reranks or silently switches the existing answer's evidence. SHA computation still costs O(bytes of used evidence), not zero database work. Final authorization/evidence check remains immediately before audit/completed output. Contract-stream checks preserve their existing source/context behavior; this change targets the portfolio-wide amplification, not a global private authorization cache.

Groq Q&A output limit is 1536 tokens; structured full review retains its separate 8192 default. Existing 90s timeout/two pre-response retries remain limits, **not** measured typical latency. Stream timeout is 120s; partial output never retries/replays. Content-free timings separate retrieval, first content, provider duration, total duration, retry count and provider queue time (null when absent). The DeepSeek hosted planner and its US$1/three-admission/consent/reservation rules are untouched.

Deterministic ASGI/fake-model tests assert answer content arrives before the provider release gate, cancellation closes the provider, partial/final failure behavior, expiry/revocation/deletion, citations, audit guarantees, cross-tenant denial and JSON compatibility. Browser/proxy/parser/hook tests cover UTF-8 framing, abort propagation and superseded scopes. Local first-content improvement is protocol-level, not a paid-provider total-generation speedup claim. Actual proxy buffering and provider cancellation behavior remain owner staging checks.

Reproduce with `python -m unittest tests.test_qa_streaming tests.test_qa_provider`, `python -m tests.qa_retrieval_benchmark`, and dashboard Q&A stream/hook/proxy tests. All use synthetic documents and fake adapters, never a paid model.

Follow-up resource/whole-stream tests: `tests.test_qa_stream_resources` (and its opted-in `PostgresStreamResourceTests`). `scripts/benchmark-qa-stream.py WORKTREE OUTPUT` runs the same complete-stream workload against both revisions: 100/1000 portfolios with ~20KB synthetic sources, three samples and three deliberately shortened fake-provider heartbeat intervals. It records rank passes/full-text rows/bytes, all SELECTs, hash-only checks, pool occupancy and first/provider/total durations. This is not a live-provider timing or proof that generation itself is faster.
